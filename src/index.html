Which robot the console looks for, and how it is finding it.

No robot has introduced itself A robot running FrcCatalyst 1.10 or later publishes its name and specification the moment it boots, and this fills in on its own. Nothing needs configuring here — if it is blank, the robot has not said.
Units How measurements read on the sheet above and across the board. The robot always publishes metric — this converts for display, so nothing on the wire changes. FRC writes its frame and height rules in inches.
Team number Sets the addresses below. Stored by the app, not by the browser, so every layout on this machine looks for the same robot.
Addresses tried The console cycles these until one answers — simulation on this machine, the field's mDNS name, the pit's static IP, then the USB tether.
    A change applies on the next connection attempt, which is about a second away while disconnected.

    Field view

    How the field tile draws. Every change lands on the tile as you make it.

    Camera Which camera the field tile is using. The buttons in the tile's own corner move this same setting. Chase follows the robot, overhead looks straight down, free holds still.
    Trail length How much of the path behind the robot is kept on screen. Zero draws no trail at all.

    Baked field model Draws the official field CAD when a build has one bundled. Switched off, the tile keeps the procedural outline, which costs a fraction as much to draw on an older laptop and tells the driver the same thing.

    Dashboard

    The board itself — how it travels between driver stations, and how long it holds on to what it is told.

    Opens on Which view the console comes up in. A team that lives in Tune during a practice day should not have to press a key to get there every launch.
    Export the layout Plain JSON. Commit it next to your robot code and every laptop in the pit comes up with the same board.
    Import a layout Checked whole before anything is applied. A file with a single bad tile in it is refused with the reason, and the board you are looking at is left alone.
    Paste it in by hand For a machine where neither the file dialog nor the clipboard is available.
    Reset the board Back to the layout the console ships with. Anything you have added or moved is discarded, so it asks once.
    Alert hold An alert that clears is held on screen, dimmed, for this long. Robot alerts sitting near their threshold raise and clear repeatedly, and a tile that strobes next to a driver is worse than useless.

    Data

    What the console will and will not make up.

    Demo data Feeds every tile from a synthetic robot so the board can be looked at without one.

    Demo data is a match on repeat: twenty seconds of auto, then teleop counting down, with a drivetrain, a battery under load and a pose driving a circle. It exists for setting a board up in the hotel the night before, and for showing someone what a tile does without a robot on the cart.

    It is off by default and it is never remembered. A dashboard that quietly invents telemetry is a hazard, so switching it on is deliberate, the dock button stays lit the whole time it runs, and a restart always comes back to real data or to nothing at all. Switching it on stands this panel down as well, exactly as a robot enabling does — a live board is what matters the moment anything goes live.

    The three rules

    Everything here answers to these, in order, and they are not negotiable.

    1. 01

      It never controls the robot.

      FRC requires the official NI Driver Station, and only one driver station may hold the robot connection. There is no code path in this program that opens that socket. It reads NetworkTables and writes only what a dashboard writes — a tunable, an auto chooser selection — and the backend refuses the control namespaces regardless of what the interface asks for.

    2. 02

      Nothing it does may impede driving.

      No modal blocks the dashboard. No check gates anything. No update prompt ever lands between a driver and their robot. This panel closes itself the instant the robot is enabled, and every failure degrades to a dimmed number and a quiet chip in a corner, because a console that interrupts is worse than no console.

    3. 03

      It never invents a number.

      An unpublished topic shows a dash, never a plausible value. Demo data has to be switched on deliberately and says so on screen while it runs. The .dslog parser refuses versions it does not recognise rather than decoding them into nonsense.
